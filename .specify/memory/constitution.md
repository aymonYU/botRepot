# YouTube Bot Report Constitution

## Core Principles

### I. 模块化架构
每个功能模块必须独立、可测试、可复用：
- YouTube API 订阅模块独立处理视频获取
- AI 分析模块独立处理内容分析
- 通知模块独立处理消息发送
- 每个模块都有清晰的输入输出接口
- 模块之间通过明确的数据结构通信

### II. 类型安全
使用 TypeScript 和 Zod 确保类型安全：
- 所有配置使用 Zod schema 验证
- API 响应数据必须类型化
- 避免使用 any 类型
- 使用严格的 TypeScript 配置

### III. 错误处理
完善的错误处理和日志记录：
- 所有异步操作必须有错误处理
- 使用结构化日志记录关键操作
- API 调用失败要有重试机制
- 错误信息要清晰、可追踪

### IV. 配置驱动
所有关键配置通过环境变量管理：
- 敏感信息不硬编码
- 提供 .env.example 作为模板
- 配置加载时验证必需字段
- 支持开发和生产环境区分

### V. 简洁高效
保持代码简洁、性能优化：
- 使用 Bun.js 获得最佳性能
- 避免不必要的依赖
- API 调用要有合理的缓存策略
- 定时任务要防止重复执行

## 技术栈约束

### 必需技术栈
- **运行时**: Bun.js
- **Web框架**: Hono.js
- **AI模型**: Gemini Flash (通过 OpenAI 兼容 API)
- **YouTube API**: Google APIs
- **类型验证**: Zod
- **通知**: Nodemailer (邮件) + Webhook 支持

### 代码规范
- 使用 TypeScript
- 使用 ESM 模块系统
- 函数式编程优先
- 异步操作使用 async/await
- 代码要有适当的注释

## 开发流程

### 功能开发
1. 使用 Speckit 规划功能
2. 定义清晰的接口和类型
3. 实现核心逻辑
4. 添加错误处理
5. 编写必要的测试

### 质量保证
- 确保类型安全
- 验证错误处理
- 检查日志记录
- 测试 API 集成
- 验证配置加载

## Governance

本项目遵循以下原则：
- 安全第一：API 密钥等敏感信息严格保护
- 稳定性：定时任务要有容错机制
- 可维护性：代码清晰，文档完整
- 性能：合理使用缓存，避免频繁 API 调用
